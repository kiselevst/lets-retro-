   Со слов заказчика (этап 6): нынешнее отображение (подписанные строки

   При взятии в работу — отдельный проход по дизайну этой карточки.
3. **Задача (cron/keep-alive), которая раз в 5 дней стучится в Supabase.**
   Со слов заказчика (этап 9). Бесплатный тариф Supabase приостанавливает
   проект после 7 дней без обращений к API — данные не теряются, но доска
   не откроется, пока кто-то вручную не нажмёт Restore в дашборде. Раз в
   5 дней с запасом укладывается в это окно. При взятии в работу —
   определиться с механизмом: Vercel Cron Job (проще всего, раз проект и
   так на Vercel) дергает лёгкий API-роут, который делает любой минимальный
   запрос к Supabase (например `select 1`), либо GitHub Actions по расписанию,
   либо внешний аптайм-монитор (см. ссылки, которые обсуждали, — есть готовые
   бесплатные варианты без написания кода).
4. **Секретный токен модератора.**
   Со слов заказчика (этап 9). Сейчас статус "я модератор этой доски"
   определяется только тем, лежит ли `participantId` с ролью moderator в
   localStorage именно этого браузера (см. `lib/participant.ts`) — если
   зайти по той же ссылке с другого устройства/браузера или после очистки
   данных, доска откроется, но уже как для обычного участника: не будет ни
   кнопки "⚙ Настройки", ни доступа к "Мои доски" оттуда же. При взятии в
   работу — продумать какой-то переносимый способ подтвердить модератора
   (например, секретный токен в отдельной ссылке "для модератора", который
   можно один раз скопировать и использовать на любом устройстве, не
   заводя полноценную аутентификацию).
